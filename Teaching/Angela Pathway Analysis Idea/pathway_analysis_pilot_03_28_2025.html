Setting up biomaRt

biomaRt provides access to a variety of online databases largely regarding information about genes. This includes a wide variety of things like orthologs from one species to another (that’s how hsapiens_to_ocellaris.csv was made), gene length, gene chromosome location, and much more that I wont go into here.

Relevant to our idea here, biomaRt provides gene ontology (GO) terms, that describes the biological process a gene plays a role in. GO terms are essentially hierarchical, meaning if a gene plays a role in lets say “androgen biosynthesis”, it will also be classified as playing a role in “steroid hormone metabolism”, “cholesterol metabolism”, “oxioreductase activity” etc., because those are all more generic ways of describing androgen biosynthesis. Additionally, genes are often enriched for several GO terms simply because they have several functions. Thus, each gene has several GO terms. Lets see what we can do with this info below.

What exactly do we want to ask?

I think what we are trying to ask is a few things

  1. What is the most likely enzymatic pathway DHEA is being metabolized in

  2. Do the sexes differ in the expression of this pathway or its constituents

My feeling is the best way to ask 1 is to ask which genes are most likely to occur in a series (and this is a big assumption) that they constitute a pathway. Of course this will need to be validated with literature.

Because our data is heavily 0 inflated (it is mostly 0s), we should pseudobulk the expression of each gene. Pseudobulking is taking the mean expression of a gene in an individual across all nuclei in a cluster.

Before I do any stats, I want to give the clownfish genes human gene names for the simple reason that most clownfish genes are named like LOC111577263 and human genes are easier to read. There is also the caveat that several ocellaris genes will align to one human gene.

#Extract gene names from steroid gene data
gene_names = colnames(steroid_gene_data[,4:ncol(steroid_gene_data)])

#Define a function to translate the gene names
get_human_names <- function(ocellaris_names) {
  sapply(ocellaris_names, function(gene) { #sapply applies a function across a vector into a list
    idx <- which(human_to_ocellaris$aocellaris_name == gene) #which asks which row indecies are true
    if(length(idx) > 0) { #if there is a match
      return(human_to_ocellaris$hsapiens_name[idx[1]]) #return the first result (there are often several matches)
    } else { #else
      return(gene) #keep the clownfish gene
    }
  })
}

human_names <- get_human_names(gene_names) #run the function

colnames(steroid_gene_data)[4:ncol(steroid_gene_data)] <- human_names #rename the relevant colnames using our new vector

Another way to visualize this is using a network graph, which finds networks for correlated items (in this case genes)

#Define a threshold because the whole matrix would be a mess

#Subset the correlation matrix based on that value such that there are no negative correalations

#make an undirected igraph

Hypothesis Testing Using a Random Walk

A random walk is an approach to asses inherently random processes. In our enzymatic pathway for example, lets say the correlation coefficient between HSD3B1 and HSD17B14 is 0.6. One interpretation could be that given a molecule that is processed by HSD3B1, there is a 60% chance it is passed to HSD17B14, and the same concept can be applied to the next enzyme after HSD17B14. Even though there is a 60% chance the molecule is passed to HSD17B14, for a single event, it is completely random where it ends up going. In a random walk, a node (gene) is selected as a starting point, and then based on the edge weight (correlation coefficient between the two genes), the walker chooses to step to the next node based on the correlation between the two nodes. Thus, 60% of the time, it will go from HSD3B1 to HSD17B14. After that, it then has a probability of going to the next node and the next node etc. By simulating a random walk thousands of times, we can see which pathway occurs the most frequently and is thus the most likely.

Here, as an example, we will run the random walk once. We set a starting node on the graph and specify the number of steps for the walker to take. We then look at which nodes (vertices) the walker traveled to

walk <-  random_walk(g,
                 4, #starting vertex (node), call V(g) to see the names of each vertex
                 4) #number of steps the walker will take

names(walk) # the steps the walker took
## [1] "HSD3B7" "DHRS4"  "UGT1A1" "AKR7A2" "CYP3A5"

A single random walk doesnt tell us that much though, so we need so simulate thousands of walks to feel confident about a result. Here, we stimulate it 3000 times.

out_data <- data.frame() #initialize empty data frame to put data into
for(i in 1:3000){ #specify number of iterations
  path <- random_walk(g, 
                      4,#starting node
                      4 #steps
                      )
  steps <- names(path) #see which steps the walker took
  newd <- data.frame(steps = steps, #add to data frame
                     n_step = 1:5,
                     iter = i)
  out_data = rbind(newd, out_data) #bind new data to out_data
}

Then, convert to probabilities by dividing by number of iterations

probability_data <- as.data.frame.matrix( #make a matrix from a table
  table(
    out_data$steps, out_data$n_step #that is x = 'which step', and y = 'gene', where cells are the frequency that gene was that step
    )/max(out_data$iter)) #divide by total number of iteration

Convergence

Convergence is the idea that as you repeat a random process thousands of times, the probability of a given event converges to a single number. Convergence is important for a variety of reasons, but most importantly it allows us to be confident that our result is real and not due to random noise.

We rerun the simulation but this time we store the frequency of the most likely node at each step. Then, we can see how it changes over a number of iterations. We will do it 10,000 times, which takes a bit of time to run.

conv_data <- data.frame()
temp_data <- data.frame()
for(i in 1:10000){
  path <- random_walk(g, 
                      4,#starting node
                      4 #steps
                      )
  steps <- names(path)
  newd <- data.frame(steps = steps,
                     n_step = 1:5,
                     iter = i)
  
    temp_data <- rbind(temp_data, newd)
    
    freq_data <- as.data.frame.matrix(table(temp_data$steps, temp_data$n_step)/i)
    #the same probability data above normalized for the given iteration we are on
    
    #store the frequency of the most likely gene for each step
    frequency_2 <- max(freq_data$`2`)
    frequency_3 <- max(freq_data$`3`)
    frequency_4 <- max(freq_data$`4`)
  
    iter_freq <- data.frame(
      n_iter = i,
      frequency_2=frequency_2,
      frequency_3 = frequency_3,
      frequency_4=frequency_4
    )

  conv_data = rbind(iter_freq, conv_data)
  
}

Convergence is often assessed by looking at a plot of probability over iteration. We are looking for the probability to essentially stabilize and become flat as the number of iterations increase.

plot(x = conv_data$n_iter, y = conv_data$frequency_2)
abline(v =2000)

plot(x = conv_data$n_iter, y = conv_data$frequency_3)
abline(v =2000)

plot(x = conv_data$n_iter, y = conv_data$frequency_4)
